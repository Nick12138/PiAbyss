方案 C · 右栏随行面板 + 待办中心
  1. 架构：A 的骨架 —— 侧栏三入口收敛为一个「小精灵」，对话在左（约 69%），右栏是「随行面板」，不切页、不叠覆盖层。
  2. 顶栏不变：仍是小精灵原有的「回到最新 / 新会话 / 会话列表」，没有页面级切换。
  3. 对话占主位：小精灵的「标准会话」机制原样保留 —— 转写、流式、工具卡、段分隔线、<pixie-context> 前导全部沿用，只多了一块右栏。
  4. 右栏第一块固定是待办：进小精灵就能看见待办，这是合并的核心诉求。它不只是列表，而是一个完整的待办中心：按日期分组（逾期 / 今天 / 明天 / 本周），只有「待处理 / 已完成」两个页签 —— 「进行中」不再单独分区，进行中的条目就直接排在待处理列表里，用转圈 + 强调色文字标识状态；状态靠图标表达，不靠分区。概览里的「进行中 / 已逾期」两格是「待处理」的子集，只做计数提示，不改变列表结构。
  5. 概览数字（来自 B）：待处理 / 进行中 / 已逾期 三格。折叠态由标题上的计数徽章承担，展开态看这三格。
  6. 就地展开详情（来自 B）：点条目在其下方展开正文、标签、工作区、截止，以及「交给小精灵 / 编辑 / 删除」。方寸间的「列表 + 详情」在这一栏里就合并完了，不再需要「右栏加宽为完整方寸间」那套模式。需要正文 Markdown、图片、周期设置时点「编辑」打开完整编辑器（沿用今天的 MemoPage 详情表单）。
  7. 新建待办 · 两个入口：① 速记框（与方案 A 同一套）—— 列表下方虚线输入框，Enter 直接落一条，title = 首行、#标签 自动识别、Shift+Enter 换行，管「先记下来」；② 标题行右侧的「＋」 —— 展开多功能表单，可一次设好标题 / 截止 / 标签 / 工作区，管「记的时候就分好类」。两个入口都常驻、不分页签；表单展开时速记框收起，避免两块新建 UI 叠在一起。落位：带截止的进对应日期分组（逾期 / 今天 / 明天 / 本周），不定的置顶。
  8. 计划创建在对话里：小精灵产出「计划草稿卡」内联在消息中，确认即 schedule.createJob（编辑则 updateJob）。原来 schedule-agent 整页 + 它自带的独立会话与模型通道整条删除。
  9. 周期计划默认折叠：折叠时只留一行「2 · 下次 3h12m 后」；展开是已有计划的列表与开关，创建入口只有「＋ 让精灵新建」（把引导语塞进对话输入框）。
  10. 委派任务默认折叠：汇总行直接写「1 进行中 · 1 等你回复」，展开才是原来的两层任务树，行尾仍是唯一的定位动作。
  11. 会话列表留在左下：侧栏下方仍是与普通工作区同一套的 SessionList（含「最近会话」分组头、行内日期、行尾状态点、右键菜单），只是 keepPage —— 点一行留在小精灵页加载那条历史段，不跳回 chat 页；「回到最新」在顶栏。它上面是 WorkspacePicker：小精灵工作区刻意不进工作区列表（否则会读成「第二个选中的小精灵」），所以那里没有选中态。
  12. 折叠状态持久化：按分组存 sidebarPref，与现有周期计划页的分组折叠同一套（会话列表的折叠也一样）。
  13. 窄屏（<940px）：侧栏收起，右栏落到对话区下方，三块分组纵向堆叠；输入框始终贴底。
