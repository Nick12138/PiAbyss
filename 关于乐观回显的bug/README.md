## 快速参考

### 根本原因（以勘误文档为准）
原 bug 有两层：

1. **原 bug（气泡消失）**：`sourceMessages()` 对不可投影的悬挂 `message` 条目也计数，
   `projectedMessageCount` 虚高，尾部实时消息被裁剪。—— 由 `5d60777` 修复。
2. **回归（尾部重复）**：`d305598` 错误地只对 `display:true` 的 custom_message 计数，
   但 pi 的 `session.messages` 实际包含**所有** custom 消息（display 只影响渲染），
   计数偏低导致尾部已持久化消息被重复渲染。—— 由 `b9c8711` 修复。

### 修复方法
`projectedMessageCount` 必须与 pi 的 `sessionEntryToContextMessages()` 对同一 entry 树
投影出的消息数严格同构：

- `message` 条目：仅在能投影出消息（role 为合法字符串）时计数
- `custom_message` 条目：**无条件计数**（display 只控制渲染可见性）
- `compaction`：无条件计数；`branch_summary`：非空 summary 才计数

### 修复位置
```
文件：apps/desktop/src/features/chat/transcript-model.ts
函数：sourceMessages()
行号：约 1023-1045
```

## 如果问题仍然存在

如果修复后仍然遇到类似问题，请：

1. **查看控制台错误**：打开开发者工具，检查是否有 JavaScript 错误
2. **检查会话数据**：查看 `.pi/agent/sessions/` 下的会话文件，确认是否有异常的 entry
3. **对比修复代码**：确认 `transcript-model.ts` 中的修复是否生效
4. **添加调试日志**：在 `sourceMessages()` 函数中添加 `console.log`，输出 `projectedMessageCount` 和 `messages.length`
5. **创建最小复现**：尝试创建一个包含 `display: false` custom_message 的测试会话
