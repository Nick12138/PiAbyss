# 5 · 乐观回显仍失效的根因与修复（2026-09-16）

> 前情：`b9c8711` 修复了 custom_message 计数导致的尾部重复渲染回归，
> 此后乐观回显仍间歇性失效。本文记录第三次排查的真正根因与修复。

## 现象（本次新增报告）

- 上一轮 agent **正常完成或报错结束后**，发送新消息 / 点击“继续”：
  - 用户消息气泡**不出现**（乐观回显失效）；
  - agent 确实在运行并正常回复，新回复**续接在上一条助手消息里**显示；
  - 切换会话或刷新后一切恢复正常（数据从未丢失）。

## 根因：entries 与 live messages 的**永久性数量差**（gap）

桌面端渲染对话时（`transcript-model.ts` 的 `sourceMessages()`），
`session.entries`（持久化条目树）与 `session.messages`（pi 运行时 state）通过
**数量对齐**决定“尾部活行”的起点：

```
tailStart = min(projectedMessageCount, messages.length)
```

但 pi 核心存在两条**故意“删 state 留 entry”** 的路径
（`pi-coding-agent/dist/core/agent-session.js`，注释原文为证）：

| 路径 | 代码位置 | 行为 |
|---|---|---|
| 上下文溢出 → 压缩重试 | `_checkCompaction()`（约 1582 行） | *"Remove the failed or truncated message from agent state. **It remains in session history**"* |
| API 报错 → 自动重试 | `_prepareRetry()`（约 2172 行） | *"Remove error message from agent state (**keep in session for history**)"* |

每次出错重试，会话文件里**多一条 entry**，而运行时 state 里**没有对应消息**。
重试成功后 pi 不会补回，差值 k 永久存在（直到下次 compaction 重建或重新打开会话——
重新打开时 restore 会把错误消息重新投影进 state，所以**刷新/切换即恢复**）。

### 失效链条（gap = k）

1. **静止时**：`projectedMessageCount = M + k > messages.length = M`。
2. 用户发送 → 乐观行追加到 messages 尾部 → `tailStart = min(M+k, M+1) = M+1`
   → 尾部活行区间为空 → **乐观气泡被吞掉，不渲染**。
3. 运行中 `entries` **不更新**（pi-host 只在 `agent_end`/`agent_settled` 才发带
   entries 的完整 `session.snapshot`；`entry_appended` 事件仅覆盖扩展 custom 条目，
   普通 message 条目不发），而 messages 逐条增长：
   - **k = 1**：message_start(user) 到达后用户行勉强露出；
   - **k ≥ 2**（会话历史中多次出错重试）：新用户消息整轮都被吞掉；
   - 助手回复因为中间没有用户行，被投影器的“连续 assistant 合并”逻辑
     **并入上一条助手行**——正是“agent 在上一轮对话里继续回复”的观感。
4. 会话历史中错误重试越多（实测部分会话文件含 10~30 条 `stopReason:"error"`
   助手消息），k 越大，症状越严重 → **只影响部分会话、间歇性出现**。

## 修复

`apps/desktop/src/features/chat/transcript-model.ts`：

废弃纯数量对齐，改为**顺序双指针内容对齐**（`alignedPersistedMessageCount()`）：

- 把 entries 投影出的消息列表与 `messages` 从头按序配对；
- 配对键（`messageAlignmentKey()`，WeakMap 缓存）覆盖两侧同一消息的所有形态：
  `role` + `customType`（custom）+ 文本/summary 长度与首尾采样；
  与 pi 的 `createCustomMessage`/`createCompactionSummaryMessage`/
  `createBranchSummaryMessage` 产出形状兼容；
- **P 侧跳过**：没有 live 对应物的持久化投影（被 pi 删除的错误消息）→ 跳过；
- 配对完成后，`messages` 中首个未配对位置即尾部活行起点——
  乐观气泡、流式 assistant、桌面本地 error 行都正确落入活行；
- 安全阀：连续跳过超过 64 条则回退旧的计数对齐，防止键失配导致整表重复。

新增回归测试（`transcript-model.test.ts`，gap=1/2、运行中、回合结束、
桌面本地 error、安全阀回退共 5 例）；旧算法下其中 4 例失败，新算法全部通过。
全量桌面端 146 个测试文件 / 1243 用例通过。

## 已知边界

- 运行中 `entries` 冻结、回合结束快照才刷新的机制未变；gap 会话中，用户消息
  仍要等 message_start 事件（乐观行先顶上，无可见空窗）。
- 若未来 pi 出现新的“删 state 留 entry”形态且配对键不兼容，安全阀会回退到
  旧行为（吞尾部）而非崩溃；届时应扩充 `messageAlignmentKey()`。
