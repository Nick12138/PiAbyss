## 修复的核心思路

**只在 `record.display === true` 时才对 `projectedMessageCount` 计数 +1**，确保计数与实际投影到 `session.messages` 的条目数一致。

### 修改后（修复代码）

```typescript
if (type === "custom_message") {
  const message = entryProjectedMessage(
    record,
    () =>
      ({
        role: "custom",
        customType: typeof record.customType === "string" ? record.customType : "custom",
        content: (record.content as SerializableAgentContent[] | string) ?? "",
        display: record.display === true,
        ...(record.details !== undefined ? { details: record.details } : {}),
        ...(record.presentation !== undefined ? { presentation: record.presentation } : {}),
      }) as SerializableAgentMessage,
  ) as SerializableAgentMessage;
  
  // ✅ 只有 display:true 的 custom_message 才计数
  // Only custom_message with display:true consumes a position in session.messages.
  // A custom_message with display:false remains an entry but does not appear in
  // session.messages, so counting it here would desynchronize the length-based
  // tail alignment and silently swallow live rows off the end of the transcript.
  if (record.display === true) {
    projectedMessageCount += 1;
  }
  
  sources.push({
    kind: "message",
    message,
    key: `${record.id}`,
    sourceId: record.id,
    timestamp: record.timestamp,
    extensionMessageRender: extensionMessageRenders?.[record.id],
  });
  continue;
}
```

## 关键改动点

### 1. 计数位置调整
- **修改前**：在创建 message 之前就 +1
- **修改后**：在创建 message 之后，根据 `record.display` 条件判断是否 +1

### 2. 添加详细注释
说明为什么要这样做，避免未来有人"优化"时又改错：

```typescript
// Only custom_message with display:true consumes a position in session.messages.
// A custom_message with display:false remains an entry but does not appear in
// session.messages, so counting it here would desynchronize the length-based
// tail alignment and silently swallow live rows off the end of the transcript.
```

### 3. 确保逻辑一致
- `message.display` 的值是 `record.display === true`
- 计数条件也是 `record.display === true`
- 两者完全对应，不会出现不一致

## 修复效果

### 计数准确性

**修复前（有 bug）：**
```
entries:
  1. user message
  2. assistant message
  3. custom_message (display: false)  ← 被错误计数
  4. user message (当前新发送的)

projectedMessageCount = 4  ❌ 虚高
messages.length = 3        ✓ 正确（不包含 display:false 的那条）
tailStart = min(4, 3) = 3
循环从 index=3 开始，而 messages.length=3，循环不执行
→ 新发送的用户消息被跳过，气泡消失
```

**修复后（正常）：**
```
entries:
  1. user message
  2. assistant message
  3. custom_message (display: false)  ← 不计数
  4. user message (当前新发送的)

projectedMessageCount = 3  ✓ 准确
messages.length = 3        ✓ 正确
tailStart = min(3, 3) = 3
循环从 index=3 开始，正常处理实时消息
→ 用户气泡正常显示
```

## 提交信息

```
fix(chat): 修复 custom_message display:false 导致的用户气泡消失 bug

根本原因：
在 transcript-model.ts 的 sourceMessages() 函数中，projectedMessageCount
用于计算 entries 中应投影为消息的条目数，但对于 custom_message 类型，
它无条件地对所有条目计数 +1，而实际上只有 display:true 的 custom_message
才会进入 session.messages 数组。

这导致当会话中存在 display:false 的 custom_message 时，projectedMessageCount
被虚高，使得 tailStart 位置偏大，实时尾部消息（包括刚发送的用户气泡）
被裁剪掉，不进入渲染循环。

修复方案：
只在 record.display === true 时才对 projectedMessageCount 计数 +1，
确保计数与实际投影到 session.messages 的条目数一致。

影响：
- 修复了用户消息气泡间歇性消失的问题
- 修复了已结束 Agent 回复左下角出现白色方块光标的问题
- 确保切换会话前后显示一致
```
