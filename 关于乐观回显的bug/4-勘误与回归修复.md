# 勘误与回归修复（2026-09-15）

> 本文档修正 `2-分析过程.md`、`3-修复方案.md`、`README.md` 中关于根因的记载。
> 原记载与 pi 核心代码事实**相反**，并因此引入了一个回归 bug，已于 `b9c8711` 修复。

## 勘误：display:false 的 custom_message **会**进入 session.messages

原记载声称：

> 只有 `display: true` 的 custom_message 才会进入 `session.messages` 数组

**这是错误的。** 沿三层调用链验证：

| 层 | 代码位置 | 事实 |
|---|---|---|
| 运行时 | pi-agent-core `agent.js` → `processEvents()` 的 `message_end` 分支 | **无条件** `this._state.messages.push(event.message)`，不区分 display |
| 运行时（非流式路径） | pi `agent-session.js:1107` `sendCustomMessage()` 的 `triggerTurn=false` 分支 | **显式** `this.agent.state.messages.push(appMessage)`，同样不区分 display |
| 会话恢复 | pi `session-manager.js:177` `sessionEntryToContextMessages()` | 对 `custom_message` 类型**无条件返回一条消息**（`display` 只是附带字段） |
| Host 快照 | `packages/pi-host/src/session-snapshot.ts:232` | `messages = [...session.messages, ...streamingMessage]`，无任何过滤 |

结论：**每条 custom_message 条目（无论 display 真假）都同时占据 entries 和 messages 两侧各一个位置**。`display` 只影响 desktop 是否为其渲染可见行（`customMessageVisible()`），不影响长度对齐计数。

因此：

- 修复前（`projectedMessageCount += 1` 无条件计数）对 custom_message 的计数**本来就是对的**；
- 原 bug（气泡消失）的真正修复是 `5d60777`（2026-09-13）在 `type === "message"` 分支加入的守卫——**不可投影的悬挂条目不计数**；
- `d305598`（2026-09-14）追加的 `if (record.display === true)` 守卫是画蛇添足。

## d305598 引入的回归

计数偏低 `k`（k = 会话中 display:false custom_message 条目数），`tailStart` 偏小，尾部循环把已由 entries 渲染过的**最后 k 条消息**再以 `stream:` key 加入转写：

- **场景 F**：`u1 → custom(display:false) → u2` → 用户气泡渲染两次（`user:e3` + `user:stream:2` 两行）
- **场景 G**：`u1 → a1 → custom(false) → u2 → a2` + 乐观气泡 → 重复文本静默合并进尾部 assistant 行（blocks = `["answer two","answer two"]`），同时乐观气泡仍可见

用临时 vitest 探针实证复现（探针已删除，结论沉淀为回归测试）。

**触发条件在真实使用中成立**：实际会话文件（PiAbyss 开发会话、telegram 工作区会话）中大量存在中段 `display:false` 的 `subagent-notify` 等条目，其后还有后续消息。

## 最终修复：b9c8711

**Commit**: `b9c8711`（2026-09-15）

- `apps/desktop/src/features/chat/transcript-model.ts`：custom_message 分支**恢复无条件计数**，并重写注释说明依据（运行时与恢复路径都让每条 custom_message 占据一个位置）。
- `apps/desktop/src/features/chat/transcript-model.test.ts`：新增 2 个「entries + display:false + 尾部对齐」组合场景的回归测试（原有测试只覆盖纯 messages 路径，未能拦住该回归）。

完整修复由两个 commit 构成，缺一不可：

| Commit | 内容 | 解决的失同步方向 |
|---|---|---|
| `5d60777`（09-13） | `message` 分支：不可投影条目不计数 | 计数**虚高** → 吞尾部消息（原 bug：气泡消失） |
| `b9c8711`（09-15） | `custom_message` 分支：恢复无条件计数 | 计数**偏低** → 尾部重复（回归：气泡/答案重复） |

两条规则共同保证不变式：`projectedMessageCount` 与 pi 的 `sessionEntryToContextMessages()` 对同一 entry 树投影出的消息数**严格同构**。

## 教训

1. 计数逻辑必须与事实源（pi 的 `sessionEntryToContextMessages`）**逐分支同构**，凭直觉加条件守卫前先核对两侧语义。
2. 测试必须覆盖「entries + 隐藏 custom + 尾部对齐」的组合场景，纯 `messages` 路径的测试拦不住对齐类回归。
